# 0.4.1 — Book references and terminology lookup

This release adds typed semantic retrieval for the first four Harry Potter
books. The same book-scoped glossary command now works for *Philosopher's Stone*,
*Chamber of Secrets*, *Prisoner of Azkaban* and *Goblet of Fire*.
It brings the book-by-book work into one release, with a rewritten README and
clearer guidance on choosing references.

## What you can use

Search people, places, notable objects and identified human-cast spells by
English or Hungarian names and concepts. The inventories contain 997 per-book
records across 94 chapters: 432 characters, 217 places, 283 objects and 65 spells.
There are also 192 selective series glossary entries, 62 evidence cards and a
199-chapter bilingual catalogue for all seven books.

For terminology, run this from the installed skill folder:

```sh
node scripts/hp.mjs glossary --book PS --query "float feather" --limit 3
node scripts/hp.mjs glossary --book GoF --category spell --query "Killing Curse" --limit 3
```

Results give compact terms, paired evidence, a formula/name classification and a
`detailsCommand` for the full record. This lets a writer resolve wording first,
then inspect mechanics and attribution when the scene needs them.

The typed records preserve distinctions that matter in a story: ordinary versus
demonstrably magical objects, failed versus successful casts, missing speech
versus proven non-verbal casting, and an event versus its later identification.
PoA and GoF records also distinguish identity reveals, different observations of
one cast, the real and impersonated Moody, and object activation.

Hungarian drafts can use `lint-hu --file DRAFT --book BOOK` for advisory term
checks. It leaves the draft unchanged. The router now supplies a working
book-scoped lookup default, and the CLI has focused glossary/facts help.

## Compatibility and scope

- **PS glossary results changed:** `glossary --book PS` now searches the full typed
  inventory, rather than the earlier selective PS glossary projection. IDs,
  categories, order and returned fields can differ. Scripts consuming this route
  should use the typed result fields and test their queries.
- All four book-scoped glossary routes support `person`, `place`, `object`,
  `spell` and `creature` (indexed animals). Other selective glossary categories
  remain available without a book filter.
- Unfiltered glossary lookup keeps its selective series behavior. It is not an
  edition-specific fallback. Evidence-card book filters still support PS only.
- Whole-book records can include later revelations. An anchor filter finds
  evidence; it does not enforce viewpoint knowledge. A missing result is not
  proof that something never occurs in canon.
- Typed retrieval for the last three books remains planned. Seven-book chapter
  metadata and the selective series references do not imply complete typed coverage.

Books and full-text passages are excluded from the package. Bundled queries
work without them; passage search and reading require your own local files.

## Validation and writing evaluation

The release passed 94 automated tests, package validation, source checks and an
isolated installation smoke test. Source checks cover 6,956 semantic locators
and the recorded bilingual chapter conversions; they do not certify full-book
semantic reading or independent editorial review.

The preserved GoF pilot used fresh writing contexts and blind model judges.
Results were mixed and do not establish general writing superiority. The new
lookup and routing changes have mechanical regression coverage; a new behavioral
writing evaluation and Hungarian human editorial review remain pending.
See the [pilot record](../gof-writing-pilot.md) and
[sample index](../../samples/README.md) for the existing evidence.

## Install

```sh
npx skills add https://github.com/lakatos-alex/hp-writing-skill/tree/v0.4.1 --skill harry-potter-fanfic
```

Guidance has no runtime requirement. Optional tools require Node.js 22 or newer,
with no third-party runtime dependencies. The project is distributed through
GitHub and the skills CLI.
