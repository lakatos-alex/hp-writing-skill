# Knowledge development

Use for expanding this skill, developing a story's background research, or organising new knowledge. This is a development mode; it permits broad source work when requested.

## Start with a coverage map

Separate available sources, mechanically indexed sources, passages actually read, and conclusions supported by those passages. A complete local corpus makes deep research possible; it does not automatically verify every sentence of a reference library.

Plan research around questions or domains. For a full-book study, read in ordered chunks and record progress by chapter and offsets. For a cross-book mechanism, compare explanation, use, failure and later reinterpretation. Retain a list of unresolved questions rather than forcing premature synthesis.

## Promote useful knowledge

A new note should change a writing or research decision. Store:
- A concise claim in original words.
- Its evidence type and source anchor.
- Scope: time, speaker, situation or exception.
- A practical writing consequence.
- What remains uncertain.
- A verification status.

Use the evidence-card fields in [facts.json](../data/facts.json) for maintained machine-readable facts. Topic lists and frequency counts help retrieval; they are not semantic verification.

## Give material a home

Shared purpose and routing belong in SKILL.md. A substantial task procedure belongs in its workflow module. Domain knowledge belongs in a focused reference. Reusable deterministic transformations belong in scripts. Raw books and private manuscript text remain in local source storage.

Add a discoverable link when adding a resource. Avoid orphan modules, duplicate facts and parallel ledgers. A useful library may be large; its top-level router should remain readable. Keep the stronger claim with its qualifications in one maintained place.

## Extra knowledge

Keep three extension categories explicit:
1. Other franchise material: identify medium and edition/date.
2. Real-world research: identify the source and which scene assumption it supports.
3. Creative proposals: record internally consistent inventions without claiming external authority.

Use outside knowledge to enrich what the books leave open—material culture, teaching methods, workplace logistics, multilingual interaction—while keeping book-canon claims grounded in the novels. A supplementary source cannot silently override a primary event.

## Model growth and portability

Prefer semantic instructions and adjustable tools over assumptions about one model's context size or tool provider. Larger context can support a whole-arc audit or full-chapter comparison. Smaller contexts can follow the same workflow with retrieval and handoff notes.

Default retrieval sizes are conveniences, not bans on deeper reading. Explicit research depth belongs to the user and task. Keep scripts executable independently and describe inputs, outputs, side effects and limits.

## Release evidence

Run structural, tool and source checks separately. Behavioural tests must record an actual result, not only an expected answer. When independent evaluation is available for a substantial change, run realistic requests without supplying the intended response. Inspect what the agent did, including whether it loaded relevant sources and respected the host story.

Update documentation, coverage and release instructions to the actual implementation. Never claim full semantic verification from title extraction, keyword hits or a successful package build.
